## 0. 测试准备

### 0.1 角色账号矩阵（务必齐）

| 代号 | 角色 | 建议账号 | 权限要点 |
|------|------|----------|----------|
| R-Admin | Admin 或 Manager | `manager` / `123456` | 建项目/Task；**唯一可改需求进展**；可改测试状态与周进度 |
| R-Lead | Task 测试负责人（Engineer） | 如 `xiaojun` | 可改自己 Task；**不可改需求进展**；测试中可 +Action、填周进度 |
| R-Owner | 仅 Action 本周负责人（非 lead） | 自备 | 可日更；不可改需求进展；一般不可改 Task |
| R-Tester | 同 Task 测试人员（非 lead、非某 Action owner） | 自备 | 看板可见；无日更权、无改进展权 |
| R-Other | 无关工程师 | 自备 | 只读有限；不可改 |
| R-Anon | 未登录 | — | 仅公开深链只读 |

### 0.2 数据准备（二选一）

**方式 A（推荐）**：`backend` 下执行

```text
python scripts/seed_tpt_realistic_board.py
```

项目 **TPT v2.1**，约 20 Task 覆盖六阶段。

**方式 B**：手工建项目 `【需求测】` + 领域，按用例逐步建 Task。

### 0.3 入口

| 模块 | 路径 |
|------|------|
| 工作台 | 登录 → 项目管理 → 工作台 Tab |
| 需求大屏 | 项目管理 → 大屏 → **需求总览** |
| 公开深链 | `/tm-screen?view=pipeline`（或 `view=req`） |

### 0.4 六阶段速查

```text
待开发 → 开发中 → 待提测 → 待测试 → 测试中 → 测试完成
```

| 阶段 | 关联时间（可待定） | +Action | 本周进度 | 测试状态下拉 |
|------|-------------------|---------|----------|--------------|
| 待开发 | 无 | 否 | 否 | 一般不展示 |
| 开发中 | 无 | 否 | 否 | 否 |
| 待提测 | 预计提测 | 否 | 否 | 否 |
| 待测试 | 实际提测 | 否 | 否 | 否 |
| 测试中 | 开始 + 预计结束 | **是** | **是** | **是** |
| 测试完成 | 结束 | 否 | 否 | 只读完成语境 |

# 一、工作台 · 需求进展

## 1.1 正向用例

| ID | 标题 | 角色 | 前置 | 步骤 | 期望 |
|----|------|------|------|------|------|
| WB-P01 | 新建 Task 默认待开发 | R-Admin | 有项目/领域 | 新建 Task 保存 | 需求进展=待开发；卡片无「+ Action」 |
| WB-P02 | 进度抽屉结构 | R-Admin | 任意 Task | 操作 → **进度** | 上半需求进展+时间；下半本周进度；可保存 |
| WB-P03 | 详情只读进展 | R-Admin | 任意 Task | 操作 → **详情** | 展示当前进展 Tag；提示改流程去「进度」；详情内不能改阶段 |
| WB-P04 | 全链路推进（填日期） | R-Admin | 新 Task | 依次：待开发→开发中→待提测(填预计)→待测试(填实际)→测试中(填开始+预计结束)→测试完成(填结束) | 每步保存成功；各阶段对应时间控件出现正确 |
| WB-P05 | 测试中出现 +Action | R-Admin / R-Lead | Task=测试中 | 看卡片 | 有「+ Action」；可新建草稿/发布 |
| WB-P06 | 测试中可填周进度 | R-Admin / R-Lead | Task=测试中 | 进度抽屉填本周进度保存 | 成功；看板进度更新 |
| WB-P07 | 进入测试中同步测试状态 | R-Admin | Task=待测试 | 改为测试中保存 | 测试状态变为进行中（或与产品一致的 published） |
| WB-P08 | 进入测试完成同步 | R-Admin | Task=测试中 | 改为测试完成保存 | 测试状态变为已完成；无 +Action |
| WB-P09 | 阶段 Tag 颜色 | R-Admin | 六阶段各一 | 看卡片/抽屉 Tag | 六色不同（灰/青/金/橙/蓝/绿） |
| WB-P10 | 进度菜单对 lead 可见 | R-Lead | 自己是 lead 的 Task | 操作菜单 | 有「进度」「详情」 |

| WB-B12 | 连续快速切换阶段保存 | R-Admin | 连续改 3 次阶段点保存 | 最终状态与最后一次一致，无脏写 |

# 二、需求大屏（需求总览）

## 2.1 正向用例

| ID | 标题 | 角色 | 步骤 | 期望 |
|----|------|------|------|------|
| SC-P01 | 进入需求总览 | R-Admin | 大屏 → 需求总览 | 标题「需求进展总览」；6 个阶段 KPI |
| SC-P02 | 默认展示全阶段 | R-Admin | 不点 KPI | 列表含待开发/开发中/待提测/待测试/测试中/**测试完成**（有数据时） |
| SC-P03 | KPI 点击筛选 | R-Admin | 点「测试完成」 | 仅该阶段；再点取消或恢复默认回全量 |
| SC-P04 | KPI 数字正确 | R-Admin | 对照工作台计数 | 各阶段 KPI = 该项目下该阶段 Task 数 |
| SC-P05 | 列结构 | R-Admin | 看表头 | 仅 Task / 领域 / 需求进展 / 负责人 |
| SC-P06 | 无 Action 展开 | R-Admin | 点测试中多 Action 的行 | **不能**展开 Action 明细 |
| SC-P07 | 负责人单人 | R-Admin | 多 Action owner 的 Task | 负责人列只有 **lead 一人**，无「等N人」 |
| SC-P08 | 无进度无风险列 | R-Admin | 看表 | 无进度条、无风险/阻塞列 |
| SC-P09 | 筛选·需求进展 | R-Admin | 筛「开发中」 | 列表仅开发中 |
| SC-P10 | 筛选·域 | R-Admin | 选某域 | 仅该域 |
| SC-P11 | 筛选·负责人 | R-Admin | 选某 lead | 仅该 lead 的 Task |
| SC-P12 | 恢复默认 | R-Admin | 改筛选后点恢复默认 | 回到全量默认 |
| SC-P13 | 阶段颜色 | R-Admin | 看 Tag / KPI 左边条 | 六阶段颜色可区分 |
| SC-P14 | 与本周切换 | R-Admin | 需求总览 ↔ 本周 | 本周可展开 Action、有进度风险；总览保持需求维度 |
| SC-P15 | 公开深链 | R-Anon | 打开 `/tm-screen?view=pipeline` | 只读可见；有数据/空态正常 |
