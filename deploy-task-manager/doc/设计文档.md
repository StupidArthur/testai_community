# 设计文档：62 定时任务管理平台

## 1. 运行时架构

```
guardian（端口 9000）
  └─ deploy-task-manager.exe（端口 8000）
        ├─ FastAPI：任务 CRUD / 立即执行 / 运行历史
        ├─ APScheduler：cron 触发
        └─ task_hooks：动态加载 tasks/<name>/run.py → 写 SQLite → 钉钉 webhook
```

任务脚本不打进 exe，始终从 exe 同级 `tasks/` 读取。因此第三方库若只出现在 `tasks/` 内，PyInstaller 默认不会打进包。

## 2. 模块职责

| 模块 | 职责 | 对外入口 |
|------|------|----------|
| `main.py` | 进程入口：灌 .env、启调度、启 Web | `main()` |
| `packaging_deps.py` | 仅采集动态任务依赖，无业务 | 被 `main.py` import |
| `scheduler.py` | cron 同步、触发 | `start_scheduler` / `run_poll_loop` |
| `task_hooks.py` | 加载 run.py、记事件、发运行报告 | `run_task` / `Callback` |
| `actions.py` | 调度器到 hooks 的薄封装 | `execute_task` |
| `tasks.py` | 扫描任务目录、读 config.json | `validate_task` / `scan_available_tasks` |
| `db.py` | SQLite：tasks / runs / run_events | 表操作函数 |
| `app.py` | REST API | `create_app` |

## 3. 动态任务依赖采集（本次设计）

**问题：** `alg_monitor` 使用 `httpx` / `boto3` / `dotenv`，运行时由 `importlib` 加载。PyInstaller 只分析 `main.py` 的静态 import 图。

**方案（双保险）：**

1. `main.py` 在业务 import 之前 `import packaging_deps`，分析器从入口就能扫到这些库，frozen 运行时也能 `import httpx`。
2. `deploy-task-manager.spec` 的 `hiddenimports` 仍列出同一批库；`build_exe.cmd` **只**用该 spec 打包，禁止删除 spec 后 `--onefile` 现场生成。

不把 `ding_api` 改成标准库 `urllib`：MinIO Console 登录依赖 cookie 会话，改动面大，且与本次故障无关。

## 4. 运行报告发群

`task_hooks._send_webhook`：任务跑完后 POST 钉钉自定义机器人。

地址优先级：`tasks/<name>/config.json` 的 `webhook.url` → 环境变量 `PLATFORM_WEBHOOK_URL`。

文案：任务可提供 `build_webhook(payload)`；否则用默认 text「【keyword】显示名 · 运行报告」。

| 目录 | 周期 | 依赖（exe 内必须有） |
