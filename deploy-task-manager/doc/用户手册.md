# 用户手册：部署与运行（62）

## 1. 目录约定

62 上工作目录（guardian 配置）：

```
D:\deploy-task-manager\deploy\
  deploy-task-manager.exe
  .env
  tasks\
  frontend\dist\
```

Web：`http://<62>:8000`  
Guardian：`http://<62>:9000`

## 2. 开发机重新打包

在开发机进入 `deploy\`，执行 `build_exe.cmd`。

要求：

- 必须保留 `deploy-task-manager.spec`，脚本不会再删除它。
- 打包前会安装 `requirements.txt`（含 httpx / boto3 / python-dotenv）。
- 产物：`deploy\dist\deploy-task-manager.exe`

拷到 62 时覆盖 exe，**不要**用开发机 `.env` 覆盖 62 的 `.env`。`tasks\` 若有业务改动一并覆盖。

## 3. 62 上生效

1. 覆盖 `deploy-task-manager.exe`（及需要更新的 `tasks\`）。
2. 在 guardian 面板重启 `deploy-task-manager`。
3. 打开平台 Web → 找到「算法版本监测」→ 立即执行一次。
4. 运维群应收到运行报告：成功则不再是 0s + `No module named 'httpx'`。

注意：立即执行会走真实采集并可能写钉钉文档、发运维群。验收窗口请选业务可接受的时间。

## 4. 平台级配置（`deploy\.env`）

| 变量 | 含义 |
|------|------|
| `PLATFORM_NAME` | 运行报告里的平台名 |
| `DINGTALK_KEYWORD` | 钉钉机器人关键词，写入报告正文 |
| `PLATFORM_WEBHOOK_URL` | 默认运行报告 webhook；任务 config.json 的 url 优先 |

## 5. 任务级配置

每个 `tasks/<name>/config.json`：

- `trigger`：cron（5 或 6 段，day_of_week 按 Unix：0=周日）
- `display_name`：报告标题用的显示名
- `timeout`：超时秒数（展示/约定）
- `webhook.url` / `webhook.keyword`：覆盖平台默认

`alg_monitor` 另需同目录 `.env`：`APP_KEY` / `APP_SECRET` / `OPERATOR_ID`。

## 6. 开发机冒烟（不发群、不写文档）

在 `deploy\` 下执行：

```
python smoke_e2e.py
```

会加载全部任务模块、打平台 API，**不会**真正跑任务、发运行报告、调用 64 或写钉钉文档。

## 7. 故障对照

| 现象 | 处理 |
|------|------|
| 耗时 0s，`No module named 'httpx'` | exe 未包含依赖：用当前仓库 `build_exe.cmd` 重打并替换 62 的 exe |
| 任务成功但运维群无报告 | 查 `PLATFORM_WEBHOOK_URL` 与任务 `webhook.url` |
| 运维群有报告、业务群无日报 | 62 只负责触发；业务发群在 64 |
| 进程起不来 | 看同目录 `task-manager.log` / `task-manager-error.log` |
