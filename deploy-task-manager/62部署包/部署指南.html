62 服务器部署指南

v2.0 极简版 · 没有任何脚本，双击 exe 就是安装，管理全在网页面板

第一部分：在开发机上准备部署包
1

确认部署包已经生成

在你的开发机（就是现在这台电脑）上，打开文件管理器，找到这个路径：

d:\代码\testai_community\deploy-task-manager\62部署包\

里面有两个文件夹：guardian 和 deploy。

完整的目录结构长这样：

62部署包/ ├── deploy/ 任务管理平台 │ ├── deploy-task-manager.exe 主程序（8000 端口） │ ├── .env 配置文件 │ ├── frontend/ │ │ └── dist/ 网页前端文件 │ └── tasks/ 定时任务脚本 │ └── guardian/ 守护程序（就 3 个文件） ├── guardian.exe 守护主程序，双击即启动 ├── services.json 守护配置 └── 使用说明.txt 文字版说明
v2.0 把安装、启动、停止、重启、卸载全部做进了 guardian.exe 和网页面板，所以 guardian 文件夹里不再有任何 cmd / ps1 脚本。
第二部分：把文件传到 62 服务器
2

远程连接 62 服务器

用远程桌面（mstsc）连接到 62 服务器，就是你平时连的那台。

如果你平时是用别的方式传文件（比如共享文件夹、FTP），也行，把文件传过去就好。

3

在 62 服务器上创建目录并复制文件

在 62 服务器的 D 盘根目录下，确保有这个结构（之前部署过就直接覆盖）：

D:\ └── deploy-task-manager/ ├── deploy/ ← 把部署包 deploy 里的内容复制进来 └── guardian/ ← 把 guardian.exe 和 services.json 复制进来
操作方法：开发机上打开对应文件夹 → 全选（Ctrl+A）→ 复制（Ctrl+C）→ 62 上打开目标文件夹 → 粘贴（Ctrl+V）
如果覆盖 guardian.exe 时提示"文件正在使用"，说明 guardian 还在跑：打开网页面板 http://62服务器IP:9000 → 右上角点「停止守护」→ 再复制 → 复制完双击 guardian.exe。
第三部分：启动（这就是安装）
4

双击 guardian.exe

在 62 服务器上，打开 D:\deploy-task-manager\guardian\ 文件夹，双击 guardian.exe。

第一次双击会弹出"用户账户控制"（UAC）窗口，点「是」。

这次双击会自动完成所有安装动作：开机自启 + 每分钟看门狗（guardian 自己挂了会被拉起）+ 防火墙放行 9000 端口。之后再双击就不会弹权限窗口了。

启动过程大约需要 10 秒左右（exe 要先解包），之后浏览器打开：

本机访问：  http://127.0.0.1:9000
其他电脑：  http://62服务器IP:9000
看到深色面板、顶部显示绿色「自启任务：已安装」，部署完成！面板上两个服务（deploy-task-manager、imgagent-server）会自动被拉起并守护。
日常操作速查（全在网页面板）

面板右上角 3 个按钮

按钮作用什么时候用
重启守护重启 guardian 自己改了配置、升级了 exe 之后；面板几秒后自动恢复
停止守护停掉 guardian（被守护的服务不受影响、也不会被自动拉起）要覆盖 guardian.exe 文件之前
卸载删除自启任务和防火墙规则不再需要守护的时候

停止之后想再启动：双击 guardian.exe 就行。

更新代码后怎么生效

改了什么怎么操作
guardian.exe 本身面板点「停止守护」→ 覆盖 exe → 双击 guardian.exe
deploy-task-manager.exe覆盖到 deploy\ 目录 → 面板上该服务卡片点「重启」（或等 30 秒自动拉起）
前端页面（frontend/dist/）复制新 dist 到 62 → 浏览器按 Ctrl+Shift+R 强刷
任务脚本（tasks/ 下的 run.py）复制新文件到 62 → 不用重启，下次定时触发自动生效
配置文件（.env）复制新 .env 到 62 → 面板上该服务点「重启」

要加新服务怎么搞

  1. 打开 http://62服务器IP:9000
  2. 点右上角绿色按钮 + 添加服务
  3. 填表：服务名、进程名、exe 路径（端口可以不填，会自动探测实际监听端口）
  4. 点「保存」，立刻就开始守护了，不用重启任何东西

出问题了看哪里（按顺序）

  • 面板底部「事件日志」表格 —— 每次拉起、失败原因、端口被谁占了都在里面
  • guardian-error.log —— 有这个文件说明 guardian 启动失败，原因直接写在里面
  • 端口显示被 PID 占用 —— 直接点面板上的「释放端口」按钮一键解决
