62 服务器服务守护部署手册

目标：把现在“cmd 跑着、窗口一关服务就死”的网页服务，改成后台常驻、开机自启、崩溃自愈的守护服务。一套脚本管多个服务，任意 python / java / node / exe 都能注册。

一、为什么这样做

现在你用 cmd 跑 python main.py，进程是前台进程，生命周期绑在那个 cmd 窗口上——窗口被关、被误触、RDP 掉线、用户注销，服务就停了。

守护方案把它变成与 cmd 窗口无关的后台进程：没有可被误关的窗口，机器重启自动拉起，进程崩了自动重启。你还能用同一条命令把 62 上其他同样“cmd 裸跑”的服务一起接管。

Windows 服务管理器 → NSSM / 计划任务 → 你的程序 (python main.py)

二、两种后端，按需选

脚本会自动选择：把 nssm.exe 放进 daemon 目录就用 NSSM，没放就用内置 watchdog。两种用同一套命令。

维度NSSM 模式（推荐）watchdog 模式（零依赖退路）
本质真正的 Windows 服务，services.msc 可见计划任务 + 进程检测，常驻拉起
开机自启服务自启开机后 1 分钟内由 watchdog 拉起
崩溃自愈NSSM 检测退出立即重启（5 秒）每 1 分钟检测，不在就拉起
窗口无（session 0 服务）无（隐藏窗口启动）
额外依赖需下载 nssm.exe（单文件，几百 KB）无系统自带
多服务每个独立服务名，sc / services.msc 统一管共用一个 watchdog，清单统一管
建议生产首选62 无法下载 nssm 时用

三、准备清单

  1. 把 daemon 目录拷到 62，放到：D:\deploy-task-manager\daemon

    即和你的 deploy 目录同级。目录里有：svc.cmd、svc.ps1、watchdog.ps1 三个文件。

  2. （NSSM 模式才需要）下载 nssm.exe
    官网 https://nssm.cc/download 下载压缩包，解压取 win64\nssm.exe，放进 daemon 目录。

    62 若无法访问外网，从你的开发机下载后拷过去即可。跳过此步即走 watchdog 模式。

  3. 确认两个值：python 路径、端口
    在 62 管理员 PowerShell 里跑：
    # python 完整路径 (Get-Command python).Source # 当前在监听的端口（确认到底 8000 还是 8020） Get-NetTCPConnection -State Listen | ? { $_.LocalPort -in 8000,8020 }

    你现在浏览器能打开的那个端口，就是待会儿 -Arguments "main.py --port 端口" 里要填的。

四、部署步骤

所有命令都要“以管理员身份”运行。：开始菜单搜 PowerShell → 右键“以管理员身份运行”，再 cd 进 daemon 目录。
  1. 先停掉现在 cmd 里那个服务
    去那个跑着的 cmd 窗口按 Ctrl+C 关掉它（或直接关窗口）。这一步是为了避免端口被旧进程占用，导致新守护服务起不来。
    # 确认端口已释放（应无输出） Get-NetTCPConnection -LocalPort 8000 -State Listen
  2. 注册当前定时任务平台为守护服务
    cd D:\deploy-task-manager\daemon . 若 62 上 python 在 .venv 里（参考 64 的部署习惯）： .\svc.cmd add TaskManager ` -Exe "D:\deploy-task-manager\deploy\.venv\Scripts\python.exe" ` -Arguments "main.py --port 8000" ` -Dir "D:\deploy-task-manager\deploy" . 若直接用系统 python（把上一步查到的路径填进 -Exe）： .\svc.cmd add TaskManager ` -Exe "C:\Python311\python.exe" ` -Arguments "main.py --port 8000" ` -Dir "D:\deploy-task-manager\deploy"

    说明：TaskManager 是服务名，自己起，多个服务各起各的名。反引号 ` 是 PowerShell 续行符。

  3. 验证起来了
    .\svc.cmd status TaskManager .\svc.cmd list # 浏览器打开 http://10.30.144.62:8000

    NSSM 模式会显示 RUNNING；watchdog 模式若显示 STOPPED，是因为还没装守护任务，继续下一步。

  4. （仅 watchdog 模式）安装守护任务
    如果你没放 nssm.exe，必须执行一次这条，开机自启 + 每 1 分钟自愈才生效：
    .\svc.cmd install-watchdog

    NSSM 模式可跳过（服务本身已自带开机自启与重启）。

五、日常管理

命令作用
.\svc.cmd list看所有受管服务状态
.\svc.cmd status TaskManager看单个服务
.\svc.cmd start TaskManager启动
.\svc.cmd stop TaskManager停止
.\svc.cmd restart TaskManager重启（改完代码后用这个）
.\svc.cmd remove TaskManager彻底卸载该服务
services.msc（NSSM 模式）图形界面里也能看到、启停这些服务

六、接管其他“cmd 裸跑”的服务

62 上只要还有别的服务是 cmd 跑的，照葫芦画瓢，换三个值即可：

# Java Spring Boot .\svc.cmd add SpringBoot -Exe "C:\Program Files\Java\jdk-21\bin\java.exe" ` -Arguments "-jar D:\app\demo.jar" -Dir "D:\app" # Node.js .\svc.cmd add WebHook -Exe "C:\node\node.exe" ` -Arguments "server.js" -Dir "D:\nodeapp" # 任意 exe .\svc.cmd add MyTool -Exe "D:\tools\mytool.exe" -Arguments "" -Dir "D:\tools" # 看全部 .\svc.cmd list
注意：-Arguments 里不要出现“带空格的路径”，否则 watchdog 模式下检测/拉起可能拆错。带空格的路径请放到 -Dir（工作目录）里，参数只写文件名。

七、卸载

# 卸载某个服务 .\svc.cmd remove TaskManager # watchdog 模式不再需要时，连守护任务一起卸 .\svc.cmd uninstall-watchdog

八、FAQ

Q1：到底是 8000 还是 8020 端口？

你说是 8000 就填 8000。部署文档里出现过 8020（任务平台地址），两者不矛盾只是历史口径不同。以“你现在浏览器能打开的那个”为准，用第三步的 Get-NetTCPConnection 命令一查便知。端口填错了服务会起来但访问不了，改 remove 再 add 即可。

Q2：python 路径填哪个？

填“你现在 cmd 里敲的那个 python”的全路径。如果之前是 python main.py 直接跑，就用 (Get-Command python).Source 查出来的路径。若 64 那套用了 .venv，62 大概率也有，优先 D:\deploy-task-manager\deploy\.venv\Scripts\python.exe。

Q3：以 SYSTEM 账户跑，访问 64 / 发钉钉会有问题吗？

一般没有。SYSTEM 能访问网络、能读写 deploy 目录、能读同目录 .env。若发现服务起不来或访问被拒，多半是账户权限。NSSM 模式改账户：

nssm set TaskManager ObjectName ".\管理员用户名" "密码" # 或在 services.msc → TaskManager → 登录 页签里改

watchdog 模式改计划任务账户：任务计划程序 → Gateway-Watchdog → 常规 →“更改用户或组”。

Q4：日志在哪？

NSSM 模式：daemon\logs\<服务名>.out.log 和 .err.log，10MB 自动轮转。watchdog 模式：daemon\logs\watchdog.log（记录每次拉起）。

Q5：开机自启吗？

是。NSSM 模式服务设为 SERVICE_AUTO_START；watchdog 模式计划任务设了 AtStartup 触发器。机器重启后服务自动回来。

Q6：会启动多个实例抢端口吗？

不会。NSSM 一个服务名只允许一个实例；watchdog 检测到端口/进程已在就不重复拉起。重复执行 start 也安全。

Q7：改了代码怎么生效？

.\svc.cmd restart TaskManager。前端 dist 更新不需要重启，刷新浏览器即可。

九、文件清单

文件作用
daemon\svc.cmd命令入口（双击/命令行调）
daemon\svc.ps1核心逻辑：add/remove/start/stop/restart/status/list/install-watchdog
daemon\watchdog.ps1零依赖守护核心（无 nssm 时用）
daemon\nssm.exe需自行放入（放入即 NSSM 模式）
daemon\services.csv受管服务清单（add 时自动生成）
daemon\logs\运行日志
一句话上手：daemon 目录拷到 62 → nssm.exe 扔进去（可选）→ 管理员跑 .\svc.cmd add TaskManager -Exe "<python全路径>" -Arguments "main.py --port 8000" -Dir "D:\deploy-task-manager\deploy" → .\svc.cmd status TaskManager 看 RUNNING 就成。
