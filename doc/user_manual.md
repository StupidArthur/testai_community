## 1. 平台是做什么的

TestAI Community 是一个**统一的测试资产与 AI 工具平台**，主要包含：

| 模块 | 你能做什么 |
|------|------------|
| **项目管理（测试任务）** | 周 Action 看板、日更、企微日报/周报；**详细使用说明见** [test_manage_product_guide.md](./test_manage_product_guide.md) |
| **Skill 管理** | 维护 AI Agent 的 Prompt 资产：按「九维结构」编辑、版本管理、分支协作、合并发布 |
| **工具集** | 下载客户端工具（如功能录制）、进入平台集成工具（如 AI 翻译） |
| **数据清洗** | 长文档入库前质检：提炼精华、冲突检测、人工审核后写入知识库 |
| **知识库** | 上传文档、基于 RAG 的智能问答（全站共享） |

> 「工作日报」顶栏入口已暂时关闭；进度以项目管理中的 **Action 日更**为准。

此外还有 **更新日志**（查看平台版本说明）和 **用户管理**（仅管理员）。

登录后，首页 Portal 提供 **Skill 管理**、**工具集**、**数据清洗**、**知识库** 等入口卡片；顶栏可切换各模块。工具集见 **[tool_hub.md](./tool_hub.md)**；数据清洗见 **[data_cleaning.md](./data_cleaning.md)**；知识库见 **[knowledge_base.md](./knowledge_base.md)**。

## 3b. 项目管理

页内右上角 **使用说明** 与本节一致。更细产品说明见 [test_manage_product_guide.md](./test_manage_product_guide.md)。

### 模块能做什么

按周管理测试工作：维护 Task / Action、填写当日进度与风险、在大屏查看进展，并向企业微信推送日报与周报。

### 基本概念

| 概念 | 说明 |
|------|------|
| 项目 / 领域 | 工作分类 |
| Task | 跨周测试工作（不按周新建）；状态仅「进行中 / 已完成」；**周结束前**可填本周 Task 进度（周报用，未填则用 Action 平均并提示） |
| Action | 本周具体执行项（负责人、进度、风险）；仅进行中 Task 可添加；可查看跨周延续历史 |
| 周界 | 默认每周三 **17:00**；Admin/Manager 可改本周结束时刻；周报一律在结束后 **15 分钟**发送（默认 **17:15**） |

### 页面入口

| 页签 | 用途 |
|------|------|
| 本周大屏 | 查看进度、风险、「需关注」 |
| 工作台 | 「我的 Task / 其他 Task / 全部」；维护 Task 与本周 Action；可复制上周 |
| 我的 Action | 提交指派给自己的当日进度 |

### 日更

1. 打开「我的 Action」→ 填写进度与说明。  
2. 有阻塞填写风险；无阻塞则风险栏留空。  
3. 当日 **19:50** 后锁定；企业微信日报约 **20:00** 发送 **1** 条。

### 风险

以最新一条日更为准：有内容 = 开放风险；留空 = 已解除。  
复制到下一周的 Action 不带入上周风险。

### 发布与状态

- Action 发布后字段锁定；更正用「更正说明」；换负责人则新建 Action。  
- 完成前进度须为 100%。  
- Task 仅「进行中 / 已完成」：进行中可加本周 Action；已完成不可再加。需手动改状态。

### 需关注

开放风险，或仍有进行中 Action；纯草稿不计入。

### 企微推送

由部署环境的计划任务触发；超长内容会压缩为单条发送。数据与配置按部署环境隔离。

## 4. 模块一：Skill 管理

Skill 是平台里的 **Prompt 资产仓库**。每个 Skill 下有多个**分支（Branch）**，每个分支保存一系列**版本快照**。

### 4.1 核心概念（用 Git 来理解）

| 概念 | 含义 |
|------|------|
| **Skill 仓库** | 一个独立的 Agent Prompt 项目，如「UI 测试助手」 |
| **Master 分支** | 正式发布的主干，通常由 Admin 维护 |
| **Standard 分支** | 标准模板，供他人 Fork 参考 |
| **Personal 分支** | 你的个人工作区，每人每个 Skill 最多一个 |
| **版本（v0, v1, v2…）** | 每次提交产生一条不可变快照；最新版称为 **HEAD** |

### 4.2 九维结构

每个版本的 Prompt 由 **9 个维度**组成：

1. **Role**（角色）— 必填  
2. Profile（画像）  
3. Background（背景）  
4. Goals（目标）  
5. Constraints（约束）  
6. Core Skills（核心技能）  
7. Workflows（工作流）  
8. Output Format（输出格式）  
9. Initialization（初始化）

编辑时有两种模式：

- **结构化模式**：每个维度单独一个输入框，适合逐项填写  
- **纯文本模式**：用 `### Role` 等 Markdown 标题组织全文，适合从外部文档粘贴

### 4.3 操作流程

#### 流程 A：浏览已有 Skill

```
Skill 管理 → 点击某个 Skill 卡片 → 分支列表 → 点击某个分支 → 沙盒编辑页
```

1. **Skill 列表页**：展示所有 Skill 仓库卡片（名称、简介）
2. **分支列表页**：展示 master / standard / 各用户的 personal 分支  
   - 若你还没有 personal 分支，可点「**创建个人分支**」  
   - 若已有，可点「**进入我的分支**」快速跳转
3. **沙盒编辑页**：左侧版本时间线 + 右侧九维编辑器

#### 流程 B：查看历史版本

1. 在沙盒页**左侧时间线**点击任意版本（v0、v1…）
2. 右侧进入**只读模式**（标签显示 HISTORY）
3. 要编辑内容，需切回最新版本（HEAD，绿色 EDIT 标签）

#### 流程 C：提交新版本（Commit）

适用于：你在**最新版本（HEAD）**上改好了内容，要保存为新版本。

1. 在九维工作台修改内容（结构化或纯文本均可）
2. 点击底部「**提交新版本 (Commit)**」
3. 弹出 **Pre-Commit 审查** 对话框：
   - AI 会给出：审查意见、改进建议、变更总结
   - 填写「提交说明」（可选，如「优化 Constraints」）
4. 点击「**确认提交**」保存  
   - 若 AI 评估失败，可选择「**跳过审查直接提交**」
5. 成功后左侧时间线出现新版本，并自动选中

> **注意**：只有 HEAD 版本可以编辑和提交；历史版本只能查看。

#### 流程 D：Fork（从标准模板复制到个人分支）

适用于：你想基于 **Standard 标准模板** 开始自己的修改，但还没有 personal 分支内容。

1. 进入 **Standard 分支** 的沙盒页（不是你的 personal 分支）
2. 点击右上角「**Fork 到我的分支**」
3. 系统自动跳转到你的 personal 分支，内容已从 standard 复制过来
4. 之后在个人分支上按「流程 C」正常编辑、提交

#### 流程 E：合并到主干（Merge）

适用于：你的 **personal 分支** 上的改动已成熟，要发布到 **Master**。

1. 进入**你的 personal 分支**沙盒页
2. 确认当前在 HEAD 版本
3. 点击「**合并到主干**」
4. 系统将 personal 最新版本合并进 master，并生成 master 上的新版本

> Merge 按钮仅在 personal 分支且满足条件时出现；master / standard 上不会显示。

#### 流程 F：新建 Skill 仓库（仅 Admin）

1. Skill 列表页 →「**新建 Skill 仓库**」
2. 填写 name（英文标识）、display_name（显示名）、definition（简介，可选）
3. 确认创建

### 4.4 工作日报（入口已暂停）

顶栏「工作日报」已隐藏。历史能力与 API 仍保留在代码中，待与「测试任务」日更方案合并后再开放。设计说明见 [test_manage.md](./test_manage.md) §11。

### 4.5 知识库

知识库支持上传文档并进行 **RAG 智能问答**，全站用户共享。

1. 顶栏 →「**知识库**」→「**新建知识库**」
2. 进入详情页 → **上传文档**（md/txt/doc/docx/pdf/pptx/xlsx）
3. 等待文档状态变为 **可用**
4. 右侧 **知识库对话** 输入问题，查看回答与参考来源

部署、环境配置、权限与常见问题详见 **[knowledge_base.md](./knowledge_base.md)**。

## 5. 模块二：AI 翻译

将 **UI 操作录制 ZIP** 上传后，平台自动跑翻译流水线，输出中文测试用例。

### 5.1 你需要准备什么

- 一个 **ZIP 压缩包**，内含 UI 录制的动作、快照等文件（需包含 `meta.json`）
- 可选：给任务起一个名称，方便在列表里识别

### 5.2 任务状态说明

| 状态 | 含义 | 你能做什么 |
|------|------|------------|
| **排队中** | 等待执行 | 查看详情、取消 |
| **运行中** | 正在翻译 | 查看实时进度、取消 |
| **已完成** | 翻译成功 | 下载 ZIP |
| **失败** | 出错 | 查看错误信息 |
| **已取消** | 你或系统取消了任务 | — |

翻译过程大致经过：**预处理 → 阶段一 → 阶段二 → 阶段四 → 打包结果**（详情页会显示当前阶段与进度百分比）。

### 5.3 操作流程

#### 流程 A：上传并开始翻译

```
AI 翻译 → 上传录制文件 → 选 ZIP、填任务名（可选）→ 开始翻译
```

1. 进入「AI 翻译」页
2. 点击「**上传录制文件**」
3. 选择 ZIP 文件，可选填「任务名称」
4. 点击「**开始翻译**」
5. 任务出现在下方列表，状态为「排队中」或「运行中」

#### 流程 B：查看任务列表

列表支持：

- 按**任务名称**搜索  
- 按**用户**、**状态**筛选  
- 操作列：**详情** / **下载**（已完成）/ **取消**（排队或运行中）/ **删除**（Admin，且任务已结束）

有任务在跑时，列表会自动刷新。

#### 流程 C：查看详情与进度

1. 点击某任务的「**详情**」，进入任务详情页
2. 页面显示：任务名、用户、创建时间、当前阶段、进度条
3. 运行中会**实时更新**进度（无需手动刷新）
4. 失败时显示错误原因

#### 流程 D：下载结果

任务**已完成**后：

1. 在列表或详情页点击「**下载**」/「**下载结果 ZIP**」，获取完整结果包

#### 流程 E：下载 Prompt 模板（可选）

在 AI 翻译页右上角「**下载 Prompts**」，可获取平台内置的 Prompt 模板 ZIP，供了解或离线参考。

#### 流程 F：Admin 删除历史任务

Admin 在任务列表对**已结束**的任务（完成/失败/已取消）可点「删除」，清除记录（不影响他人正在运行的任务）。

## 10. 如何打开平台（简要）

### 10.1 环境配置（项目根目录 `.env`）

前后端共用**项目根目录**下的一份 `.env`（与 `backend/`、`frontend/` 同级）：

```ini
MINIMAX_API_KEY=你的MiniMax密钥
TAVILY_API_KEY=你的Tavily密钥
MIMO_API_KEY=你的Mimo密钥
ENV=dev
BACKEND_PORT=48010
FRONTEND_PORT=3003
DATABASE_URL=sqlite:///./database_dev.sqlite
```

- 首次使用：复制 `.env.example` 为 `.env` 并填写  
- **你的开发电脑** 与 **给用户用的电脑** 各用各自目录下的 `.env` + 数据库文件（如 `database_dev.sqlite`），互不影响；灌 mock / 清数据只动当前这台机器上的库  
- 同机 A/B（开发/生产两份目录）见 [deploy_ab_same_pc.md](./deploy_ab_same_pc.md)  
- `.env` 已在 gitignore 中，不会提交到仓库

### 10.2 启动

**开发环境（前后端分开）：**

```powershell
# 终端 1：后端
cd G:\deploy\testai_community\backend
python run.py

# 终端 2：前端
cd G:\deploy\testai_community\frontend
npm run dev
```

浏览器访问：**http://localhost:3003**（端口由 `.env` 中 `FRONTEND_PORT` 决定）

**一键重启（推荐，Windows）：**

在项目根目录双击 `restart_dev.bat`，或在 PowerShell 中执行：

```powershell
cd G:\deploy\testai_community
.\restart_dev.ps1
```

脚本会：① 检查并启动 Ollama、补拉模型 ② 释放 `.env` 中配置的后端/前端端口 ③ 在新窗口启动 `python run.py` 与 `npm run dev`。

单独只检查 Ollama：`scripts\ensure_ollama.bat`（知识库向量入库前可手动跑一次）。

**一体化部署（先构建前端）：**

```powershell
cd G:\deploy\testai_community\frontend
npm run build

cd ..\backend
python run.py
```

浏览器访问：**http://localhost:48010**（端口由 `.env` 中 `BACKEND_PORT` 决定）

### 10.3 生成 AI 行业早报（可选）

后台能力，无 Web 页面；由 `ai_service/news` 模块提供：

1. 在 `.env` 中配置 `TAVILY_API_KEY`（搜索）与 `MINIMAX_API_KEY`（总结）
2. 在 `backend/` 目录执行：

```powershell
cd G:\deploy\testai_community\backend
python -m app.ai_service.news
```

3. 输出 Markdown 默认写入 `<项目根>/data/ai_news/YYYY-MM-DD-AI-Daily-News.md`（近 48 小时要闻；链接经 Tavily 白名单校验）

也可在代码中调用：`await generate_daily_news()`（见 [dev/modules/ai_service.md](./dev/modules/ai_service.md)）。

## 11. 常见问题

**Q：登录后页面空白或提示未构建？**  
生产模式需先 `npm run build`；或改用开发模式 `npm run dev`。

**Q：Skill 页看不到「新建 Skill 仓库」？**  
该按钮仅 Admin 可见。

**Q：为什么不能编辑内容？**  
你可能在查看历史版本。请在左侧时间线选中带 **HEAD** 标签的最新版本。

**Q：Commit 后弹窗一直转圈？**  
可能是 AI 评估接口异常；若长时间无响应，可关闭弹窗重试，或联系管理员。

**Q：翻译任务一直排队？**  
平台默认同时只跑少量任务；请确认后端服务正常，或稍后再试。

**Q：上传 ZIP 报错？**  
确认文件为合法录制包且内含 `meta.json`；文件过大也会被拒绝。

**Q：忘记密码？**  
联系 Admin 在用户管理中重置。
