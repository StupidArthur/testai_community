## 1. 先搞清概念（1 分钟）

本平台里 **没有单独的「需求」表**：

- **Task** = 一条需求主题（标题 + 需求正文 + **需求进展** + 测试负责人）
- **Action** = 这条 Task 在「测试中」拆出来的本周具体事项（才有日更）

| 字段 | 是什么 | 谁改 |
|------|--------|------|
| **需求进展** | 待开发 → … → 测试完成（整条需求生命周期） | **仅 Admin / Manager** |
| **测试状态** | 进行中 / 已完成（测试侧） | lead 或 Admin/Manager；主要在「测试中 / 测试完成」时有意义 |

## 2. 测前准备

### 2.1 账号（密码一般是 `123456`）

| 角色 | 建议账号 | 用来测什么 |
|------|----------|------------|
| 测试管理员 | `manager` | 改需求进展、建 Task、看大屏 |
| Task 负责人 | 如 `xiaojun` / `hj` | 不能改需求进展；测试中可 +Action、填周进度 |
| 普通工程师 | 任意 Engineer | 不能改别人的进展 |

### 2.2 演示数据（推荐，六阶段都有）

在项目 `backend` 目录执行：

```text
python scripts/seed_tpt_realistic_board.py
```

会重建项目 **TPT v2.1**，约 20 个 Task，覆盖六种需求进展。测完可继续用，或再跑一遍重置。

### 2.3 入口

1. 登录 → **项目管理**
2. 项目筛选选 **TPT v2.1**（或你自己建的项目）
3. 工作台看 Task 卡片；大屏 Tab 看 **需求总览**

公开深链（免登录只读）：`/tm-screen?view=pipeline`

## 3. 必测清单（请勾选）

### A. 工作台 · 需求进展（用 manager）

| # | 步骤 | 期望 | 结果 |
|---|------|------|------|
| A1 | 新建 Task | 默认需求进展 = **待开发**；**没有**「+ Action」 | [ ] |
| A2 | Task「操作 → 进度」 | 上半是需求进展 + 时间；下半是本周进度 | [ ] |
| A3 | 改成「开发中」保存 | 成功；仍无「+ Action」 | [ ] |
| A4 | 改成「待提测」 | 出现「预计提测时间」；可清空为**待定**仍能保存 | [ ] |
| A5 | 改成「待测试」 | 出现「实际提测时间」；可待定保存 | [ ] |
| A6 | 改成「测试中」，时间可填可待定 | 保存后出现「+ Action」；测试状态多为进行中 | [ ] |
| A7 | 在「测试中」填本周进度并保存 | 成功 | [ ] |
| A8 | 改回「开发中」再看进度区 | 本周进度应**不可填**（有锁定提示） | [ ] |
| A9 | 改成「测试完成」 | 可填结束时间或待定；之后无「+ Action」 | [ ] |
| A10 | Task「操作 → 详情」 | 能看到当前需求进展；**改阶段要去「进度」** | [ ] |

### B. 权限（换账号）

| # | 步骤 | 期望 | 结果 |
|---|------|------|------|
| B1 | 用 **lead**（非 manager）打开「进度」 | **不能**改需求进展下拉（或提示仅 Admin/Manager） | [ ] |
| B2 | lead 在「测试中」的 Task | 可以「+ Action」、可填本周进度（若有权限） | [ ] |

### C. 需求总览大屏

| # | 步骤 | 期望 | 结果 |
|---|------|------|------|
| C1 | 大屏切到「需求总览」 | 标题「需求进展总览」；上方 6 个阶段 KPI 有数字 | [ ] |
| C2 | 默认列表 | **六种阶段都应能出现在列表**（含待开发、测试完成），不是只显示待提测/待测试/测试中 | [ ] |
| C3 | 点某个 KPI（如「测试完成」） | 列表只剩该阶段；再点取消或「恢复默认」回到全量 | [ ] |
| C4 | 列表列 | 只有 **Task / 领域 / 需求进展 / 负责人**；**没有**进度条、**没有**风险/阻塞列 | [ ] |
| C5 | 测试中有很多 Action 的 Task | **不能展开** Action 明细（需求维度只看 Task） | [ ] |
| C6 | 负责人列 | **只有 1 个人名**（Task 测试负责人），不要出现「某某 等4人」 | [ ] |
| C7 | 需求进展标签颜色 | 六阶段颜色不同（灰/青/金/橙/蓝/绿） | [ ] |
| C8 | 有无时间副行的 Task | 行高应一致（没有「预计提测 xx」的行也不应明显矮一截） | [ ] |
| C9 | 筛选 | 只有「需求进展 / 域 / Task 负责人」一类需求维度筛选项；**没有**「测试状态」与需求进展重复那套 | [ ] |
| C10 | 打开 `/tm-screen?view=pipeline` | 免登录能看需求总览；历史 Tab **不要**出现蓝色「历史周只读不可编辑」条 | [ ] |

### D. 与「本周」大屏的差异（防混）

| # | 步骤 | 期望 | 结果 |
|---|------|------|------|
| D1 | 切到「本周」 | 可以展开 Action；有进度、风险/阻塞 | [ ] |
| D2 | 本周「需关注」 | 默认盯交测后堵点（待测试+测试中相关），与需求总览「全阶段」不同 | [ ] |

## 4. 常见对错（测的时候对照）

| 现象 | 是否正常 |
|------|----------|
| 待开发 / 开发中没有「+ Action」 | 正常 |
| 时间清空保存，大屏写「待定」 | 正常 |
| 需求总览看不到 Action 明细 | 正常（故意的） |
| 需求总览负责人只有一个人 | 正常 |
| lead 改不了需求进展 | 正常 |
| manager 才能推进阶段 | 正常 |
