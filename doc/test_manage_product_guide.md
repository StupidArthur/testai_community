## 0. 五分钟上手

### 0.1 两种进度别混（最常问）

| 写什么 | 谁写 | 什么时候写 | 写在哪 |
| ------ | ---- | ---------- | ------ |
| **Action 日更进度** | 该条 Action 的本周负责人（owner） | **每天**有进展就写；建议 **19:50 前**；钉钉日报约 20:00 | 「我的 Action」或点开 Action 抽屉 |
| **Task 周进度** | Task lead / 测试管理员 | **每周一次**，建议 **周结束前** 手填 | 工作台 Task「操作 → 进度」 |

- 日更：进度 % + 说明必填；**风险**可选；旁有勾选 **是否阻塞**（勾选后才进日报/阻塞统计）。
- 周进度：不是每天写；未手填时周报 / 工作台「均进度」会用本周 Action 平均估算。

### 0.2 你是 Action 本周负责人？

1. 打开「**我的 Action**」  
2. 点开自己的条目 → 填**进度 %** + **进度说明**（有风险再填风险；若构成阻塞再勾选「是否阻塞」）
3. **19:50 前**保存；日更到 **100%** 会**自动标记完成**

### 0.3 你是 Task 测试负责人（lead）？

1. 打开「**工作台**」→ 找到自己的 Task  
2. 先在 Task 里维护好**子需求**（Subtask）  
3. 「**+ Action**」新建并**关联一个子需求**（必选）；上周未完成的 Action 会**自动继承**到本周（含进度）  
4. 核对负责人 / 内容 → **发布**  
5. **周结束前**手填「本周 Task 进度」  
6. 主题做完 → Task 改为「已完成」；暂不投入 →「归档」

### 0.4 你是测试管理员？

1. 「**新建**」下拉：项目 / 领域 / Task  
2. 配好钉钉 webhook 与定时任务  
3. 必要时改「周结束」时刻；抽查大屏「需关注」

## 1. 概念与层级（模块）

### 1.1 五级结构

```
Project（项目，如 TPT v2.1）
  └── Domain（领域：平台 / Agent / 交付 / 定制…）
        └── Task（主题线：需求 + 测试负责人 + 测试人员）
              └── Subtask（子需求：名称 + 内容；挂在 Task 上，不单独建表）
                    └── Action（本周事项：本周负责人 + 测试内容 + 环境；用子需求名称关联）
```

| 名词        | 一句话                     | 是否按周新建           |
| ----------- | -------------------------- | ---------------------- |
| **Project** | 组织容器；看板可按项目筛选 | 否                     |
| **Domain**  | 项目下的领域分区           | 否                     |
| **Task**    | 跨周持续的主题线           | **否**（切周不重建）   |
| **Subtask** | Task 下的子需求（名称唯一） | 否（随 Task 维护）     |
| **Action**  | 本周要执行的具体事项       | **是**（每条挂某一周） |

### 1.2 两个「负责人」别混

| 称呼                           | 主要职责                                                | 能否换人                     |
| ------------------------------ | ------------------------------------------------------- | ---------------------------- |
| **Task 测试负责人（lead）**    | 建本周 Action、管子需求、改 Task、可改本 Task 下 Action 状态 | 测试管理员 / lead 可改           |
| **Action 本周负责人（owner）** | 写日更、点完成                                          | **仅草稿可改派**；一发布锁定 |

- 二者可以是同一人，也可以不同。  
- owner **必须**从「lead ∪ 该 Task 测试人员」中选。

### 1.3 「周」怎么算

| 项          | 规则                                                                                   |
| ----------- | -------------------------------------------------------------------------------------- |
| 时区        | UTC+8                                                                                  |
| 默认切周    | **每周三 17:00**（测试管理员可改**本周结束**）                                   |
| 本周窗口    | `[起点, 结束)`；改结束后，本周 Action 截止同步                                         |
| 新建 Action | 一律挂**当前活动周**；切周时上周未完成 Action **自动继承**到新周 |
| Task 周进度 | 周结束前由测试管理员 / lead 手填（周报用）；未填则用本周 Action **平均**，并提示「未手填」 |
| 周报发送    | **周结束 + 15 分钟**（默认 17:00 → **17:15**）                                         |

**切周日（周结束当天）特殊口径：**

| 时段               | 日更 / 钉钉日报          | 新建 Action  |
| ------------------ | ------------------------ | ------------ |
| 当天 00:00～结束前 | 仍属**即将结束**的那一周 | 仍属旧周     |
| 结束后             | 当天日更仍写**旧周**     | 挂**新一周** |
| 次日 00:00 起      | 归属新一周               | 同左         |

例（默认）：周四「本周」= 昨天周三 17:00 → 下周三 17:00 前。

### 1.4 状态一览

**Action：**

```
草稿 ──发布──► 进行中 ──日更到100%（自动）/ 手动──► 完成（终态，不可重开）
```

- **不支持取消。** 建错：草稿可不发布；已发布用「更正说明」。  
- **日更进度到 100% 时自动标记完成**（无需手动点）；也可手动「标记完成」（须进度 100%）。

| Action 状态 | 改字段           | 日更              | 更正说明 |
| ----------- | ---------------- | ----------------- | -------- |
| 草稿        | ✅ 测试管理员 / lead | ❌                | ❌       |
| 进行中      | ❌ 全锁          | ✅ owner / 测试管理员 | ✅       |
| 完成        | ❌               | ❌                | ✅       |

**Task：** 进行中 / 已完成 / 归档（归档=暂不投入人力）。大屏「已完成」「归档」分开筛，只看 Task 自身状态，不会因 Action 全做完而自动归入已完成。

## 2. 角色与权限（模块）

本模块面向角色：**测试工程师**、**Task 测试负责人（lead）**、**测试管理员**（系统账号角色为 `Manager`）。

### 2.1 各角色必做 / 不能做

| 身份                     | 必须做                                           | 不能做                                             |
| ------------------------ | ------------------------------------------------ | -------------------------------------------------- |
| **测试管理员**               | 建项目 / 领域 / Task；配钉钉；必要时代写日更     | —                                                  |
| **Task lead**            | 切周后确认自动继承、建新 Action → 填内容 → **发布**；盯进度 | 不能给别人的 Action 写日更（除非自己是 owner）     |
| **Action owner**         | **每日日更**；做到 100% 自动完成                | 发布后不能改字段/改派；进度未满 100% 不能完成      |
| **同 Task 其他测试人员** | 可作为某周 owner 候选                            | 不能写他人日更；不能改草稿（除非兼 lead / 测试管理员） |
| **其他工程师**           | 可看有本周 Action 的看板                         | 无编辑权                                           |

### 2.2 权限简表

| 操作                                                    | 测试管理员 |   Task lead    | Action owner | 其他 |
| ------------------------------------------------------- | :----: | :------------: | :----------: | :--: |
| 建/改 Project、建 Domain                                |   ✅   |       ❌       |      ❌      |  ❌  |
| 建 Task                                                 |   ✅   |       ❌       |      ❌      |  ❌  |
| 编辑 Task / 手填周进度 / 改 Task 状态；归档 / 删除 Task |   ✅   |       ✅       |      ❌      |  ❌  |
| 设本周结束时刻                                          |   ✅   |       ❌       |      ❌      |  ❌  |
| 建本周 Action；改草稿                              |   ✅   |       ✅       |      ❌      |  ❌  |
| 改已发布 Action 字段                                    |   ❌   |       ❌       |      ❌      |  ❌  |
| 发布 / 完成（不可取消）                                 |   ✅   | ✅（本 Task）  | ✅（自己的） |  ❌  |
| 写日更                                                  |   ✅   | 仅自己是 owner |      ✅      |  ❌  |
| 追加更正                                                |   ✅   | ✅（本 Task）  | ✅（自己的） |  ❌  |
| 手动钉钉推送                                            |   ✅   |       ❌       |      ❌      |  ❌  |

默认演示账号：`manager` / `123456`。  
无导出；**无 Action 取消**。

## 3. 项目 · 领域 · Task（模块）

### 3.1 新建入口（工作台）

测试管理员在工作台工具栏点 **「新建」** 下拉：

| 菜单项 | 作用                                  |
| ------ | ------------------------------------- |
| 项目   | 创建 Project                          |
| 领域   | 在已选项目下建 Domain（需先选中项目） |
| Task   | 创建 Task（挂在项目 / 领域下）        |

### 3.2 Task 字段

| 字段       | 必填？          | 说明                                   |
| ---------- | --------------- | -------------------------------------- |
| 标题       | **必填**        |                                        |
| 需求内容   | 建议            | ≤ **5000** 字                          |
| 测试负责人 | **必填**        | 一人（lead）                           |
| 测试人员   | 可选            | 多人；与 lead 组成 Action owner 候选池 |
| 子需求     | 建后可加        | 名称 + 内容；Task 内不可重名；Action 必须关联其一 |
| Task 状态  | 进行中 / 已完成 | 测试管理员或 lead 可改                     |

已发布 Task 再改字段时，建议填「变更说明」。

### 3.3 Task 卡片上的「操作」

每张 Task 卡右侧有 **「操作」** 下拉（主按钮旁保留 **+ Action**）：

| 菜单     | 作用                                                         |
| -------- | ------------------------------------------------------------ |
| **详情** | 打开抽屉：基本信息 + **子需求管理**（默认只读，点小「编辑」才改） |
| **进度** | 打开抽屉，定位到「本周 Task 进度」填写区                     |
| **归档** | 归档后看板默认不再显示；下属 Action 仍保留                   |
| **删除** | **永久删除** Task 及下属数据，不可恢复                       |

### 3.4 Task 与周的关系

- Task **跨周持续**，切周**不要**重建 Task。  
- 每周在该 Task 下新建 **本周 Action**；上周未完成的会**自动继承**过来。  
- Task 收尾：由 lead / 测试管理员把 Task 状态改为「已完成」（不会自动变）。

## 4. 本周 Action（模块）

### 4.1 谁、何时可建

| 项          | 规则                              |
| ----------- | --------------------------------- |
| 谁          | 测试管理员，或该 Task **lead**        |
| 何时        | 当前周窗口内；Task 须为**进行中** |
| 已完成 Task | **不能**再加本周 Action           |

### 4.2 新建

1. 工作台 Task 卡点 **「+ Action」**，或 Task 抽屉底部「新建本周 Action」  
2. 选**子需求**（必选），填标题、本周负责人、测试内容、环境  
3. 「仅存草稿」或「保存并发布」

| 字段       | 必填？   | 说明                        |
| ---------- | -------- | --------------------------- |
| 子需求     | **必选** | 从该 Task 已建子需求中选一个 |
| 标题       | **必填** |                             |
| 本周负责人 | **必填** | 默认 = lead；只能从参与者选 |
| 测试内容   | 建议     | ≤ **1000**                  |
| 环境       | 建议     | ≤ **300**                   |
| 截止       | 系统默认 | = 本周结束                  |

### 4.3 子需求（Subtask）与自动继承

**子需求：** Task 下的二级维度，只有「名称 + 内容」两个属性；**同一 Task 内名称不可重复**。  
在 Task 抽屉（或 Task 卡片入口）维护：

| 操作   | 规则                                                                 |
| ------ | -------------------------------------------------------------------- |
| 新增   | 名称 + 内容；重名会被拒绝                                            |
| 改名   | 该 Task 下关联的 Action **自动同步**新名称                            |
| 删除   | **软删除**（保留记录）；其下**未完成** Action 自动置为**已取消**（数据保留，已完成不受影响） |

**自动继承（替代原「复制上周」）：** 切周时系统**自动**把上周**进行中（published 且未完成）**的 Action 复制到新周：

| 项         | 规则                                        |
| ---------- | ------------------------------------------- |
| 触发       | 切周时自动执行，无需任何人手动操作            |
| 继承范围   | 上周状态**非 done** 的 Action（含草稿）      |
| 进度       | **保留上周进度**（如 60%），本周从该值继续往上填 |
| 新状态     | 直接为**进行中**（published），无需再发布      |
| 已完成的   | **不继承**；上周已 100% 的 Action 留在上周    |
| 手动复制   | **已下线**：不再提供「复制上周」按钮          |

### 4.4 发布之后

- 标题、负责人、测试内容、环境等 **全部锁定**，不可直接改派。  
- 写错用「**更正说明**」追加时间线；要换负责人 → **新建一条**并指定正确 owner。  
- 操作顺序建议：草稿核对 → 发布 → 每日日更 → 日更到 100% → 标记完成。

## 5. 日更与风险（模块）

### 5.1 谁写、何时写

| 项     | 规则                                      |
| ------ | ----------------------------------------- |
| 谁     | **该 Action owner**，或测试管理员（可代写）   |
| 何时   | Action 为**进行中**；报告日期固定**当天** |
| 截止   | 当天 **19:50** 后锁定，不可再改今日日更   |
| 补历史 | **不可**；每 Action 每天一条，后写覆盖    |

lead **不能**帮别人写日更（除非自己是该条 owner，或账号是测试管理员）。

### 5.2 字段

| 字段        | 必填？   | 说明                              |
| ----------- | -------- | --------------------------------- |
| 进度 %      | **必填** | 0–100；**不可低于**当前进度（只涨不降）；**填 100% 自动标记完成** |
| 进度说明    | **必填** | 去空白后非空即可；≤1000           |
| 风险 | 有则填 | 最新一条**留空保存** = 风险文案已清空 |
| 是否阻塞 | 可选勾选 | **仅勾选**才计入开放阻塞 / 日报阻塞 / 大屏「有阻塞」；无风险文案时勾选无效 |

### 5.3 进度与风险怎么读

| 概念            | 规则                                              |
| --------------- | ------------------------------------------------- |
| Action 当前进度 | 最新一条日更的 %                                  |
| 当前风险文案    | 最新一条日更的「风险」                     |
| **开放阻塞**    | 仅 **进行中** 且有风险文案且勾选 **是否阻塞**；草稿 / 完成不计 |
| Action 均进度   | 当前筛选下各 Action 最新进度的算术平均            |
| Task 周进度     | 手填优先；未填 → Action 平均 +「未手填」提示      |

建议：风险解除 → 日更清空风险栏；做完 → 先日更到 100% 再点完成。

### 5.4 更正说明

- 用于进行中或已完成。  
- 内容必填，只追加时间线，**不改**原字段；≤1000。

## 6. 本周大屏（模块）

面向汇报。页右上角有「使用说明」；大屏支持 **今日 | 本周 | 历史**（各 Tab 筛选独立）。

| 能力 | 说明 |
|------|------|
| 今日 | 当前业务周非草稿 Action；**扁平 Action 列表**；默认「进行中 + 有阻塞」，勾选 **查看未日更**（默认开）则并入未日更 |
| 本周 / 历史 | 历史最多 **10** 周；**只读** |
| 周汇总明细 | **按子需求（Subtask）分组展示**：Action 标题放大突出，子需求 / Task 信息小字（放不下时 hover 显示） |
| 日汇总明细 | Action 条目带**关联子需求名称** |
| KPI | 今日：总 Action · 有阻塞 · 未日更 · 均进度；本周/历史：总 Task · 有阻塞 Task · 总 Action · 均进度 |
| 侧栏 | **已移除**「阻塞聚焦」；主表加宽 |
| 公开深链 | `/tm-screen?view=today`（免登录只读）；**默认项目与登录大屏一致**（优先 TPT）；可「复制今日深链」 |
| 草稿 | **大屏不展示草稿 Action**；仅草稿的 Task 整行隐藏 |

**本周/历史筛选：** 关注范围 · 需求进展 · 测试状态 · 阻塞 · 域 · 风险 · 周进度 · 含未日更 · Task 负责人 · Action 状态（单行展示，超出从末尾收进「更多」）。「需关注」默认盯 **待测试 + 测试中**。
**今日筛选：** Action 状态 · 阻塞 · 域 · 查看未日更 · 风险 · Action 进度 · 负责人 · Task 状态（同上）。
**需求总览：** 大屏第四视图；六阶段漏斗；**默认展示全部阶段**（点 KPI 可筛）；按需求/Task 展示（无 Action 明细、无测试进度与风险/阻塞列）。详见 [test_manage_req_stage_guide.md](./test_manage_req_stage_guide.md)。
各 Tab 筛选独立；可「恢复默认」。默认今日仍为「进行中 + 有阻塞 + 查看未日更」。

## 7. 工作台（模块）

面向执行与维护。

### 7.1 工具栏

1. **scope 下拉**：我的 Task / 其他 / 全部（「我的」= 你是测试负责人的 Task）  
2. **项目筛选**下拉（可搜索；清空后不会再被默认项目自动回填）  
3. 测试管理员：**新建**（项目 / 领域 / Task；未选项目时「领域」不可点；仅一个领域时新建 Task 会自动带上）  
4. 测试管理员可改「周结束」，界面显示推导的周报发送时刻  

历史周隐藏新建入口。空 Task（本周 0 Action）仅在**可建 Action**（需求进展=测试中）时标红提醒。

### 7.2 Task / Action 常用路径

| 目标             | 怎么走                                            |
| ---------------- | ------------------------------------------------- |
| 管理子需求       | Task「操作 → 详情」抽屉的**子需求管理**区：增 / 改名 / 删 |
| 建本周 Action    | Task 卡 **+ Action**（**子需求必选**）            |
| 填 Task 周进度 / 改需求进展 | 「操作 → 进度」（流程 + 本周进度同屏） |
| 归档 / 删除 Task | 「操作」菜单                                      |
| 看 Action / 日更 | 点 Task 内 Action **表格行**进抽屉                |

Task 卡片内的 Action 以**表格**展示：**子需求 · Action 标题 · 负责人 · 进度 · 状态 · 风险 · 操作**；每页最多 **20** 行，超出分页；**未日更优先**，同组按**创建时间**升序。上周未完成的 Action 切周后**自动出现**在本周表格中（带原进度）。

### 7.3 Action 抽屉里能做什么

- 草稿：编辑字段 → 发布  
- 进行中：日更、更正、标记完成（须进度 100%）  
- 查看关联**子需求**；查看**延续历史**（跨周继承链路）

- [ ] 钉钉 webhook 与定时任务正常

### Task lead（切周后）

- [ ] 确认上周未完成 Action **已自动继承**到本周（进度沿用）  
- [ ] 为本周新要点建 Action（**必须关联子需求**）  
- [ ] 指定本周负责人（须在 Task 参与者内）  
- [ ] 填测试内容 / 环境并**发布**  
- [ ] 周结束前填 Task 周进度（推荐）  

### Action owner（每天）

- [ ] 「我的 Action」提交日更（**19:50 前**）  
- [ ] 做完 → 日更到 **100%** → **自动标记完成**  

### 时间轴（默认周三切周）

```
周三 17:00 切周
  ├─ 系统自动：上周未完成 Action 继承到本周（保留进度，直接进行中）
  ├─ lead / 测试管理员：为本周新要点建 Action（关联子需求）→ 发布
  ├─ 每天（建议 19:50 前）：owner 写日更（进度只涨不降）
  ├─ 每天约 20:00：钉钉日报 1 条（无风险也发）
  ├─ 周结束前：lead 填「本周 Task 进度」（可选但推荐）
  ├─ 周结束 +15 分钟：钉钉周报
  └─ Action 日更到 100% 自动完成；Task 收尾须手动改 Task 状态
```

## 11. 常见问题

**Q：切周后上周 Action 呢？**  
A：**未完成（进度 < 100%）的自动继承**到本周：保留进度、直接为进行中，无需任何操作。已完成的留在上周，不再出现。

**Q：为什么没有「复制上周」按钮了？**  
A：已下线。切周自动继承取代了手动复制；新建 Action 走「+ Action」（关联子需求）。

**Q：子需求（Subtask）是什么？在哪维护？**  
A：Task 下的二级维度（名称 + 内容）。在 Task「操作 → 详情」抽屉的子需求管理区维护；同一 Task 内不可重名；改名自动同步关联 Action；删除会连带删除其下所有 Action。

**Q：建 Action 时子需求必选吗？**  
A：**必选**。每条 Action 必须关联该 Task 的一个子需求（只能关联一个）。

**Q：发布后负责人选错了？**  
A：不能改派、不能取消。用更正说明记录，并由正确人选另建一条（或由当前 owner 做到完成）。

**Q：lead 能帮成员写日更吗？**  
A：不能（除非自己是该条 owner，或账号是测试管理员）。可改状态、追加更正。

**Q：进度 80% 为什么不能完成？**  
A：完成须最新日更进度 = **100%**；日更填 100% 时会**自动标记完成**，无需手动点。

**Q：今天为什么不能把进度从 70 填成 50？**  
A：进度**只涨不降**，防止误操作覆盖真实进展。

**Q：能不能取消 Action？**  
A：不能。草稿可不发布；已发布用更正说明或做到完成。

**Q：完成后能改回进行中 / 再日更吗？**  
A：都不能。完成为终态；可用更正说明补文字。

**Q：「需关注」和「全部」为什么一样多？**  
A：多数 Task 仍有进行中 Action 时两者会接近。纯草稿不算需关注。

**Q：Action 都做完了，Task 为何还不在「已完成」？**  
A：「已完成」只看 Task 状态。请 lead / 测试管理员在 Task 上设为已完成。

**Q：风险第二天没了怎么写？**  
A：日更把风险栏**留空**保存即可。

**Q：切周日该给哪一周写日更？**  
A：切周当天全天仍写**旧汇报周**；新周 Action 的日更从次日起。

**Q：真实姓名在哪改？**  
A：测试管理员在「用户管理」；看板与推送优先展示真实姓名。

**Q：页内说明和下载版有什么区别？**  
A：页内是简略上手；本文件是分模块完整版。生产环境请在「使用说明」抽屉点 **下载完整使用说明**。

### 规则锚点（摘要）

1. 默认切周 **周三 17:00**（可配 week_end）；周报 = 结束 +15 分钟  
2. 发布后不可改派；完成终态；**不支持取消**；日更到 **100% 自动完成**  
3. 日更仅 owner / 测试管理员；说明非空；进度**不倒退**；仅当天；**19:50** 锁定  
4. 开放风险仅统计「进行中」  
5. 大屏「已完成」仅 done、「归档」仅 cancelled；大屏不展示草稿 Action  
6. 钉钉日报 / 周报无风险也发；单条截断不拆条  
7. **切周自动继承**上周未完成 Action（保留进度、直接进行中）；**无手动复制**  
8. Task 下有**子需求（Subtask）**；Action **必关联一个**子需求；子需求重名拒绝、改名同步、删除级联取消其未完成 Action
