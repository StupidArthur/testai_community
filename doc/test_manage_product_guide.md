## 1. 产品要解决什么问题

把「本周测什么、谁负责、进度多少、卡在哪」落到可追踪的**周任务**上，并支持：

1. **周看板汇报**（本周大屏）：领导一眼看 Task / Action 进度与风险。  
2. **个人日更**：Action **本周负责人**每日更新进度与阻塞。  
3. **企微群推送**：日报推「短进展 + 风险」（**每天发送**，无风险也发）；周报推「短进展 + 风险」。

进度以 **Action 日更**为准（旧顶栏「工作日报」入口已关闭）。

## 2. 核心概念（必读）

### 2.1 四级结构

```
Project（项目，如 TPT v2.1）
  └── Domain（领域：平台 / Agent / 交付 / 定制…）
        └── Task（主题任务：需求内容 + 测试负责人 + 测试人员）
              └── Action（本周可执行实例：本周负责人 + 测试内容 + 环境）
```

| 名词 | 含义 | 典型例子 |
|------|------|----------|
| **Project** | 组织容器；看板可按项目筛选 | `TPT v2.1` |
| **Domain** | 项目下的领域分区 | 平台、Agent、交付 |
| **Task** | 一条持续主题线；指定**测试负责人（lead）**与**测试人员** | 「业务 Agents 专项」 |
| **Action** | **仅本周**要做的具体事项；有**本周负责人（owner）** | 「设备健康 agent 测试」 |

**必须分清的两个「负责人」：**

| 称呼 | 作用 | 能否换人 |
|------|------|----------|
| **Task 测试负责人** | 建本周 Action、改 Task、可改本 Task 下 Action **状态** | 管理员 / lead 可改 Task 上的 lead |
| **Action 本周负责人** | 对本周这一条写 **日更**；点「完成」 | **仅草稿可改派**；发布后永久锁定 |

二者可以是同一人，也可以不同。本周负责人必须从「Task 测试负责人 ∪ 测试人员」中选（规则 **A1**）。

### 2.2 「周」怎么算

| 项 | 规则 |
|----|------|
| 时区 | **UTC+8** |
| 切周时刻 | **每周三 18:00** |
| 本周窗口 | `[本周三 18:00, 下周三 18:00)`（左闭右开） |
| 新建 Action | 一律挂到 **`current_week_start`（当前周）**；**不会**自动生成下周 Action；**无一天内几点前/后的创建时间限制** |
| 截止时间 | 默认 = 本周窗口结束（下周三 18:00） |

**切周日（周三）特殊口径：**

| 时段 | 日更 / 企微日报归属 | 新建 Action 归属 |
|------|---------------------|------------------|
| 周三 00:00～17:59 | **仍属上一汇报周**（以当天 18:00 为终点的那一周）；**不要**给新一周 Action 写日更 | 仍属上一周（18:00 前 `current_week_start` 指上一周） |
| 周三 18:00 起 | 日更仍写**上一汇报周**直至当天结束 | 新 Action 挂**新一周** |
| 周四 00:00 起 | 日更 / 日报归属**新一周** | 同左 |

例：今天是周四，则「本周」从昨天（周三）18:00 开始，一直到下周三 18:00 前。

### 2.2b 谁、何时可建 Action

| 项 | 规则 |
|----|------|
| 谁可建 | **Admin / Manager**，或该 Task **测试负责人（lead）** |
| 何时可建 | **当前周窗口内随时**（Action 始终挂 `current_week_start`，无「几点前才能建」限制） |
| 草稿 → 发布 | lead / 管理员可发布任意本 Task 草稿；**Action 本周负责人本人**也可发布/完成**自己的** Action（见 §5 权限矩阵） |
| 从上周复制 | 同上权限；复制后仍挂当前周 |

### 2.3 Action 状态机

```
草稿(draft) ──发布──► 进行中(published) ──完成──► 完成(done)     【终态，不可重开】
```

> **Action 不支持取消。** 建错可保留草稿不发布，或发布后用「更正说明」纠错；历史库中若有 `cancelled` 仅作只读存量，大屏默认不展示。

| 状态 | 界面文案 | 改标题/负责人/内容/环境 | 写日更 | 追加更正说明 | 说明 |
|------|----------|---------------------------|--------|--------------|------|
| 草稿 | 草稿 | ✅ 管理员 / Task 负责人 | ❌ | ❌ | |
| 进行中 | 进行中 | ❌ **全部锁定** | ✅ owner / 管理员 | ✅ | 开放风险只统计此状态；**进度须先日更到 100% 才能点完成** |
| 完成 | 完成 | ❌ | ❌ | ✅ | **终态**，不可改回进行中 |

谁可以改状态：管理员、该 Task 测试负责人、**该 Action 本周负责人本人**。

### 2.4 Task 状态

Task **仅两种状态**：由管理员或 Task 测试负责人在「编辑 Task」中修改。

| 状态 | 界面文案 | 可否加本周 Action |
|------|----------|-------------------|
| `published` | 进行中 | ✅ 可以 |
| `done` | 已完成 | ❌ 不可新建 / 复制 Action |

创建 Task 时默认直接进入「进行中」（发布）。**不再提供** Task 草稿 / 取消。

**与大屏「已完成」Tab 的关系（纯 Task 维度，与 Action 无关）：**

- Task **只有**在自身状态为 **已完成（done）** 时，才会出现在「已完成」Tab。  
- **不会**因为本周 Action 全部做完就把 Task 归入「已完成」；Action 全做完只影响 Action 维度 KPI 与「需关注」筛选。  
- 主题线已收尾时，请由 lead / 管理员在 Task 上**显式**设为「已完成」。

## 3. 角色与「每个人必须做什么」

系统账号角色：`Admin` / `Manager` / `Engineer`。  
在项目管理模块里，`Admin` 与 `Manager` **权限相同**（下文合称**管理员**）。

### 3.1 一句话职责

| 身份 | **必须**做什么 | **不能**做什么 |
|------|----------------|----------------|
| **管理员** | 建项目 / 领域 / Task；指定 lead 与测试人员；监督大屏；配置企微；必要时可代写日更 | — |
| **Task 测试负责人** | 每周切周后：为本周建 Action → 填测试内容 / 环境 → **发布**；推动成员完成 | **不能**给「别人负责」的 Action 写日更（除非自己也是该条 owner）；**不能取消 Action** |
| **Action 本周负责人** | **每日日更**（进度 % 必填；有阻塞填风险）；做完先把进度日更为 **100%**，再点「完成」 | 发布后不能改字段 / 改派；进度未满 100% 不能完成；完成后不能再日更、不能重开 |
| **Task 测试人员（非本周 owner）** | 可作为某周 Action 的负责人候选 | 不能写他人日更；不能改草稿字段（除非同时是 lead / 管理员） |
| **其他工程师** | 可看有本周 Action 的看板 | 无编辑权 |

### 3.2 典型一周时间线

```
周三 18:00 切周
    │
    ├─ Task 负责人 / 管理员：为当前周新建 Action（或从上周复制）→ 填内容 → 发布
    │         · 18:00 后新建的 Action 挂新一周；其日更从周四起写
    │
    ├─ 每天（建议 19:50 前）：Action 负责人写日更
    │         · 进度 0–100（必填，不可倒退）
    │         · 进度说明必填（去空白后非空即可，无最少字数）
    │         · 风险/阻塞（有则填写；清空 = 已解除）
    │         · 仅写当天；19:50 后锁定
    │         · 切周日（周三）全天：日更仍写「以当天 18:00 为终点」的那一周
    │
    ├─ 每天 20:00：企微【日报】——短进展 + 风险；**无开放风险也每天发送**
    │
    ├─ 周三 17:30：企微【周报】——短进展 + 风险，无风险也发进展
    │
    └─ （可选收尾）Action 进度 100% 后点「完成」；Task 进「已完成」须 lead/管理员改 Task 状态
```

## 4. 字段必填清单

### 4.1 创建 / 维护 Task

| 字段 | 必填？ | 说明 |
|------|--------|------|
| 标题 | **必填** | Task 名称 |
| 需求内容 | 强烈建议 | 上限 **5000** 字 |
| 测试负责人 | **必填** | 一人 |
| 测试人员 | 可选 | 可多人；与 lead 一起构成 Action 负责人候选池 |
| Task 状态 | 进行中 / 已完成 | 管理员或 lead 可改；已完成不可再加 Action |

已发布 Task 再改字段时，建议填写「变更说明」（写入更新日志）。

### 4.2 创建本周 Action

| 字段 | 必填？ | 说明 |
|------|--------|------|
| 标题 | **必填** | 本周事项名 |
| 本周负责人 | **必填** | 默认 = Task lead；只能从 lead + 测试人员选 |
| 测试内容 | 强烈建议 | 上限 **1000** 字 |
| 环境 | 建议填写 | 上限 **300** 字 |
| 截止 | 系统默认 | 本周窗口结束 |

草稿可改负责人与内容；**一点「发布」全部锁定**。写错请用「更正说明」，**不要指望改派负责人**。

### 4.3 日更（仅「进行中」；owner 或管理员；当天 19:50 前）

| 字段 | 必填？ | 说明 |
|------|--------|------|
| 进度 % | **必填** | 0–100；**不可低于**该 Action 当前进度；下调用「更正说明」 |
| 进度说明 | **必填** | 去空白后**非空**即可（**无最少字数**）；上限 1000 |
| 风险 / 阻塞 | 有阻塞时应填 | 最新一条为空 = **风险已清除** |
| 报告日期 | 固定当天 | **不可补历史日**；每个 Action 每天仅一条，谁写谁覆盖 |

**窗口**：当天可多次改写，至 **19:50**（含之前）截止；之后锁定，企微日报默认 **20:00** 发送。

### 4.4 更正说明（进行中或已完成）

| 字段 | 必填？ | 说明 |
|------|--------|------|
| 更正内容 | **必填** | 只追加时间线，不改原字段；上限 1000 |

## 6. 进度与风险怎么算（产品口径）

| 概念 | 规则 |
|------|------|
| **当前进度** | 该 Action **最新一条**日更的进度 % |
| **当前风险文案** | 最新一条日更的「风险 / 阻塞」 |
| **风险已清除** | 最新日更把风险留空（即使历史上写过） |
| **开放风险**（大屏「有风险」、企微风险段） | 仅 **进行中** 且最新风险**非空**；草稿 / 完成（及历史取消）**一律不计** |
| **Action 均进度** | 当前筛选下，各 Action 最新进度的**算术平均** |
| **Task 行负责人** | **Task 测试负责人在前**；本周另有 Action owner 时显示「张三 等 N 人」 |

建议：

- 风险解除但任务未完 → 日更时清空风险栏。  
- 任务做完 → 先日更到 **100%** 再点「完成」（旧风险字也不会再进开放风险）。

## 7. 企微日报 / 周报（产品说明）

### 7.1 前置条件

服务端 `.env`（或环境变量）示例：

```env
WECOM_WEBHOOK_URL=https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的key
WECOM_PUSH_ENABLED=true
# 可选覆盖时刻（默认如下）
# WECOM_DAILY_PUSH_HOUR=20
# WECOM_DAILY_PUSH_MINUTE=0
# TM_DAILY_EDIT_LOCK_HOUR=19
# TM_DAILY_EDIT_LOCK_MINUTE=50
# WECOM_WEEKLY_PUSH_WEEKDAY=2   # 周三=2
# WECOM_WEEKLY_PUSH_HOUR=17
# WECOM_WEEKLY_PUSH_MINUTE=30
```

**推荐定时方式：Windows 计划任务**（不依赖 `python run.py` 常驻）：

```powershell
# 在 backend/scripts 目录执行一次
.\configure_wecom_push_power.ps1   # 睡眠=从不（可选加固）
.\install_wecom_scheduled_tasks.ps1  # 日报/周报 + 自动安装 keep-awake
# 或单独：.\install_wecom_keep_awake.ps1
```

- **锁屏/熄屏可以**；设置页「睡眠=从不」在 **Modern Standby** 本上往往仍会进连接待机，必须再跑 **`TestAI-WeCom-KeepAwake`**（登录保活，不强制亮屏）。  
- 日报任务调用 `backend/scripts/wecom_scheduled_push.py`（kind=daily，默认 **20:00**）。  
- 周报任务同上（kind=weekly，默认**周三 17:30**）；若晚于周三 18:00 补跑，仍汇报刚结束周。  
- 若已用计划任务推送，请设 **`WECOM_PUSH_ENABLED=false`**，避免 `run.py` 进程内调度**重复发送**。  
- 未配 webhook 时不会真发；可用 `dry_run` 预览。  
- **无常开服务器时**：依赖本机插电 + keep-awake；不要结束 `TestAI-WeCom-KeepAwake` 任务。

### 7.2 日报（默认每天 20:00）

| 项 | 说明 |
|----|------|
| 日更截止 | 当天 **19:50** 后不可再写/改今日日更 |
| 汇报周 | 取 `daily_context_week_start`（**切周日周三全天仍属上一汇报周**） |
| 侧重点 | **Action 粒度**：今日谁提交了哪些日更；**当前开放风险**（新增 / 未解决） |
| 发什么 | 周期 + Action 速览 + **按负责人列出今日 Action** + 当前风险明细 |
| 消息条数 | **固定 1 条**；上限 **4096 字节**；先缩条目，再 **AI 压缩**，最后硬截断 |
| 无开放风险 | **仍每天发送**（可仅有今日进展） |
| 人名 | 优先 **真实姓名**，否则用户名 |
| 谁触发 | Windows 计划任务（推荐）；或 `run.py` 进程内调度；或管理员手动接口 |

### 7.3 周报（默认周三 17:30，切周前）

| 项 | 说明 |
|----|------|
| 侧重点 | **Task + 整体进度 + 风险**：Task/Action KPI、分领域均进度、Task 进度列表；风险按 **Task 视角**展示 |
| 发什么 | 周期 + 整体进度 + **本周 Task 进度** + 风险（新增 / 未解决 / 已消除） |
| 消息条数 | **固定 1 条**；上限 **4096 字节**；规则同日报（截断 → AI → 硬截断） |
| 无风险 | **仍发送**整体与 Task 进展 |
| 谁触发 | 计划任务 / 进程内调度 / 管理员手动 |

### 7.4 和「人必须填什么」的关系

| 成员动作 | 对推送的影响 |
|----------|----------------|
| 日更写了风险 | 可能进**当日日报**与**周报风险段** |
| 日更清空风险，或 Action 完成 | 不再算开放风险 |
| 全员都不写风险 | **日报仍发**短进展；周报仍发进展 |

管理员手动：

- `dry_run=true`：只预览，不落库不发群。  
- `force=true`：忽略「本日 / 本周已推过」幂等。  

调试脚本：`backend/scripts/trigger_wecom_push.py`（改 `__main__` 参数，勿用命令行参数）。

### 7.5 文案结构（示意）

**日报**（Action 视角）：周期、今日按负责人的 Action 日更、当前风险明细。

**周报**（Task 视角）：周期、整体 KPI / 分领域均进度、本周 Task 进度列表、风险（先 Task 后 Action）。

二者均 **单条 ≤4096 字节**；超长先缩列表，再调 AI 压缩，最后硬截断。

## 8. 界面使用指南

项目管理页三个 Tab：

### 8.1 本周大屏（默认）

面向领导汇报。

**周切换（本周 / 历史）：**

| 模式 | 行为 |
|------|------|
| **本周** | 当前业务周看板；可新建 / 编辑（按权限） |
| **历史** | 只读快照；下拉选择最近最多 **10** 个业务周（不含本周）；仅展示该周确有 Action 的 Task；不可编辑 / 日更 / 改状态 |

工作台与大屏共用同一套切换；历史模式下隐藏「新建项目 / 领域 / Task」。

**KPI（两行，避免口径混淆）：**

| 行 | 含义 |
|----|------|
| **Task 维度** | 合计 / 进行中 / 完成 / 草稿 / 有风险（该 Task 下是否存在开放风险 Action） |
| **Action 维度** | 合计 / 进行中 / 完成 / 草稿 / 有风险 / **Action 均进度** |

**明细筛选（与领域 chip 同款样式）：**

| Tab | 含义 |
|-----|------|
| **需关注**（默认） | 仍有进行中 / 草稿 Action，或存在开放风险 |
| **全部** | 当前项目 / 领域下板内全部 Task |
| **已完成** | **仅 Task 维度**：Task 自身状态为 **已完成**；**不因** Action 全做完而归入 |

排序：有风险优先，再按进度升序（落后在前）。右侧「风险聚焦」列出开放风险项。支持全屏汇报。

若「需关注」与「全部」数量相同：说明每个 Task 下至少还有一条未完成 Action——属正常现象。Action 全做完**不会**自动把 Task 移入「已完成」。

### 8.2 工作台

面向执行与维护：

1. 按项目筛选（可选）。  
2. 管理员：新建项目 → 领域 → Task（指定负责人与测试人员）。  
3. Task 负责人：在 Task 下「新建本周 Action」→ 草稿编辑 → **发布**。  
4. 可从上周 Action **复制**到本周。  
5. 点开 Action 抽屉：变更状态、日更、更正时间线。

工作台顶部「本周速览」数字均标明 **Action** 口径（进行中 / 完成 / 草稿 / 进行中有风险 / 均进度）。

### 8.3 我的 Action

只列出：**当前周** + **本周负责人 = 当前登录用户**。  
日常建议：工程师主要在此写日更、点完成。

### 8.4 Action 抽屉操作顺序

1. **草稿**：核对标题、负责人、测试内容、环境 → 「发布」。  
2. **进行中**：每天日更；字段写错用「更正说明」。  
3. **做完**：先日更进度到 **100%** → 「标记完成」（未满 100% 按钮禁用；完成后不可日更、不可重开）。  

> 无「取消」按钮：Action **不支持取消**。

### 管理员

- [ ] 项目 / 领域 / Task 人员是否齐套

### Task 测试负责人（每周切周后）

- [ ] 为本周每个要点建 Action（或从上周复制）  
- [ ] 指定本周负责人（人选必须在 Task 参与者内）  
- [ ] 填测试内容 / 环境并**发布**

- [ ] 提交日更（**19:50 前**）：进度 %（不倒退）；说明去空白后非空；有阻塞写风险  
- [ ] 全部做完 → 日更到 **100%** → 「标记完成」

## 10. 常见场景问答

**Q：切周后上周 Action 怎么办？**  
A：不会自动带过来。Task 负责人在本周新建，或用「从上周复制」。

**Q：发布后发现负责人选错了？**  
A：发布后**不能改派**，也**不能取消**该条。请用「更正说明」记录情况，并由正确人选另建一条 Action（或继续由当前负责人执行到完成）。

**Q：Task 负责人能不能帮成员写日更？**  
A：**不能**（除非自己也是该 Action owner，或账号是管理员）。可改状态、追加更正。

**Q：进度 80% 为什么不能点完成？**  
A：最新日更进度必须为 **100%** 才能标记完成（后端也会拒绝）。请先提交日更把进度改为 100%。

**Q：能不能取消一条建错的 Action？**  
A：**不能。** Action 已取消功能；草稿可不发布，已发布请用更正说明，或做到 100% 后标记完成。

**Q：完成后还能改进度吗？**  
A：不能日更。可用「更正说明」补充文字；开放风险也不再统计该条。

**Q：完成后能改回进行中吗？**  
A：**不能**。完成为终态。

**Q：大屏「需关注」和「全部」为什么一样多？**  
A：「需关注」= 有开放风险，或仍有**进行中** Action；**纯草稿不算**。若很多 Task 仍有进行中 Action，两者会接近。

**Q：Action 都做完了，为什么 Task 还在「需关注」？**  
A：「已完成」Tab 只看 **Task.status**。请 lead / Manager 在 Task 上设为「完成」。

**Q：第一天写了风险，第二天没了怎么操作？**  
A：第二天日更把风险栏**留空**保存即可；以最新日更为准，开放风险消失。

**Q：企微没收到日报？**  
A：查 webhook / 计划任务 / 保活；日报**每天应发送**（含无风险日），且始终 **1 条**（超长 AI 压缩）。

**Q：真实姓名在哪改？**  
A：Admin「用户管理」维护；推送与看板优先展示真实姓名。启动回填只补空值，不覆盖手工修改。

### 规则锚点（与早期讨论差异，以本文为准）

1. **发布后不可改派**本周负责人（字段全锁）；仅**草稿**可改负责人。  
2. **`完成` 为终态**，不可重开为进行中；**Action 不支持取消**。  
3. **完成后不可日更**；开放风险仅统计「进行中」。  
4. **标记完成须最新日更进度 = 100%**（未满则按钮禁用且接口 400）。  
5. 日更：**仅**本周负责人或管理员；**说明去空白后非空（无最少字数）**、进度不倒退、仅当天、**19:50 锁定**；企微日报默认 **20:00**，**每天发送**（含无风险日）。  
6. **大屏「已完成」Tab 仅 Task 维度**（Task.status = done）；Action 全做完**不**归入。
7. **切周日（周三）**：日更 / 日报仍属上一汇报周；18:00 后可建新周 Action，其日更从周四起。  
8. **环境字段上限 300 字**；测试内容仍 1000 字。  
9. **企微推送推荐 Windows 计划任务**；用计划任务时设 `WECOM_PUSH_ENABLED=false`。
