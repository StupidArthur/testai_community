## 1. 要解决什么

把「本周测什么、谁负责、进度多少、卡在哪」落到可追踪的**周任务**上：

1. **本周大屏**：领导看 Task / Action 进度与风险  
2. **个人日更**：Action 本周负责人每日更新进度与阻塞  
3. **企微推送**：日报 / 周报各发 **1** 条（无风险也发）

进度以 **Action 日更**为准（旧「工作日报」入口已关闭）。

## 2. 核心概念

### 2.1 四级结构

```
Project（项目，如 TPT v2.1）
  └── Domain（领域：平台 / Agent / 交付 / 定制…）
        └── Task（主题线：需求 + 测试负责人 + 测试人员）
              └── Action（本周事项：本周负责人 + 测试内容 + 环境）
```

| 名词        | 含义                       |
| ----------- | -------------------------- |
| **Project** | 组织容器；看板可按项目筛选 |
| **Domain**  | 项目下的领域分区           |
| **Task**    | 跨周主题线；不按周新建     |
| **Action**  | **仅本周**的执行实例       |

**两个「负责人」不要混：**

| 称呼                           | 职责                                               | 能否换人                     |
| ------------------------------ | -------------------------------------------------- | ---------------------------- |
| **Task 测试负责人（lead）**    | 建本周 Action、改 Task、可改本 Task 下 Action 状态 | 管理员 / lead 可改           |
| **Action 本周负责人（owner）** | 写日更、点完成                                     | **仅草稿可改派**；发布后锁定 |

二者可同可异。owner 必须从「lead ∪ 测试人员」中选。

### 2.2 「周」怎么算

| 项          | 规则                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------ |
| 时区        | UTC+8                                                                                            |
| 默认切周    | **每周三 17:00**（Admin / Manager 可改**本周结束**）                                             |
| 本周窗口    | `[起点, 结束)`；改结束后，本周 Action 截止同步                                                   |
| 新建 Action | 一律挂**当前活动周**；不自动生成下周                                                             |
| Task 周进度 | 周结束前由 Admin / Manager / lead 手填（周报用）；未填则用本周 Action **平均**，并提示「未手填」 |
| 周报发送    | **一律周结束 + 15 分钟**（默认 17:00 → **17:15**）                                               |

**切周日（周结束当天）特殊口径：**

| 时段               | 日更 / 企微日报                 | 新建 Action  |
| ------------------ | ------------------------------- | ------------ |
| 当天 00:00～结束前 | 仍属**刚结束/即将结束**的那一周 | 仍属旧周     |
| 结束后             | 当天日更仍写**旧周**            | 挂**新一周** |
| 次日 00:00 起      | 归属新一周                      | 同左         |

例（默认）：周四「本周」= 昨天周三 17:00 → 下周三 17:00 前。

### 2.3 谁、何时可建 Action

| 项         | 规则                                         |
| ---------- | -------------------------------------------- |
| 谁         | Admin / Manager，或该 Task **lead**          |
| 何时       | 当前周窗口内随时                             |
| 从上周复制 | 同上权限；复制后仍挂当前周；**不带上周风险** |

### 2.4 Action 状态

```
草稿 ──发布──► 进行中 ──完成──► 完成（终态，不可重开）
```

**不支持取消。** 建错：草稿可不发布；已发布用「更正说明」，或做到 100% 后标记完成。

| 状态   | 改字段           | 日更              | 更正说明 |
| ------ | ---------------- | ----------------- | -------- |
| 草稿   | ✅ 管理员 / lead | ❌                | ❌       |
| 进行中 | ❌ 全锁          | ✅ owner / 管理员 | ✅       |
| 完成   | ❌               | ❌                | ✅       |

完成条件：最新日更进度必须 = **100%**。  
谁可改状态：管理员、该 Task lead、**该 Action owner 本人**。

### 2.5 Task 状态

仅两种（创建即「进行中」）：

| 状态   | 可否加本周 Action |
| ------ | ----------------- |
| 进行中 | ✅                |
| 已完成 | ❌                |

大屏「已完成」Tab **只看 Task 自身状态**，不因 Action 全做完而自动归入。

## 3. 角色与必做

系统角色：`Admin` / `Manager` / `Engineer`。模块内 Admin ≡ Manager（下称**管理员**）。

| 身份                     | 必须做                                           | 不能做                                             |
| ------------------------ | ------------------------------------------------ | -------------------------------------------------- |
| **管理员**               | 建项目 / 领域 / Task；配企微；必要时代写日更     | —                                                 |
| **Task lead**            | 切周后建/复制 Action → 填内容 → **发布**；盯进度 | 不能给别人的 Action 写日更（除非自己是 owner）     |
| **Action owner**         | **每日日更**；做完先日更到 100% 再点完成         | 发布后不能改字段/改派；进度未满 100% 不能完成      |
| **同 Task 其他测试人员** | 可作为某周 owner 候选                            | 不能写他人日更；不能改草稿（除非兼 lead / 管理员） |
| **其他工程师**           | 可看有本周 Action 的看板                         | 无编辑权                                           |

### 典型一周

```
周三 17:00 切周
  ├─ lead / 管理员：新建或复制本周 Action → 发布
  ├─ 每天（建议 19:50 前）：owner 写日更（进度不倒退；说明非空；有阻塞填风险）
  ├─ 每天约 20:00：企微日报 1 条（无风险也发）
  ├─ 周结束前：lead 填「本周 Task 进度」（可选但推荐）
  ├─ 周结束 +15 分钟：企微周报
  └─ Action 进度 100% → 标记完成；Task 收尾须手动改 Task 状态
```

## 4. 字段必填

### Task

| 字段       | 必填？          | 说明                            |
| ---------- | --------------- | ------------------------------- |
| 标题       | **必填**        |                                 |
| 需求内容   | 建议            | ≤ **5000** 字                   |
| 测试负责人 | **必填**        | 一人                            |
| 测试人员   | 可选            | 多人；与 lead 组成 owner 候选池 |
| Task 状态  | 进行中 / 已完成 | 管理员或 lead 可改              |

已发布 Task 再改字段时，建议填「变更说明」。

### 本周 Action

| 字段       | 必填？   | 说明                        |
| ---------- | -------- | --------------------------- |
| 标题       | **必填** |                             |
| 本周负责人 | **必填** | 默认 = lead；只能从参与者选 |
| 测试内容   | 建议     | ≤ **1000**                  |
| 环境       | 建议     | ≤ **300**                   |
| 截止       | 系统默认 | = 本周结束                  |

草稿可改；**一发布全锁**。写错用「更正说明」，不要指望改派。

### 日更（仅进行中；owner 或管理员；当天 19:50 前）

| 字段        | 必填？   | 说明                                         |
| ----------- | -------- | -------------------------------------------- |
| 进度 %      | **必填** | 0–100；**不可低于**当前进度                  |
| 进度说明    | **必填** | 去空白后非空即可；≤1000                      |
| 风险 / 阻塞 | 有则填   | 最新一条留空 = **已解除**                    |
| 报告日期    | 固定当天 | **不可补历史**；每 Action 每天一条，后写覆盖 |

### 更正说明（进行中或已完成）

内容必填，只追加时间线，不改原字段；≤1000。

| ------------------------------------------- | :----: | :------------: | :----------: | :--: |

| 建 Task                                     | ✅     | ❌             | ❌           | ❌   |
| 编辑 Task / 手填 Task 周进度 / 改 Task 状态 | ✅     | ✅             | ❌           | ❌   |
| 设本周结束时刻                              | ✅     | ❌             | ❌           | ❌   |
| 建/复制本周 Action；改草稿                  | ✅     | ✅             | ❌           | ❌   |
| 改已发布 Action 字段                        | ❌     | ❌             | ❌           | ❌   |
| 发布 / 完成（不可取消）                     | ✅     | ✅（本 Task）  | ✅（自己的） | ❌   |
| 写日更                                      | ✅     | 仅自己是 owner | ✅           | ❌   |
| 追加更正                                    | ✅     | ✅（本 Task）  | ✅（自己的） | ❌   |
| 手动企微推送                                | ✅     | ❌             | ❌           | ❌   |

默认演示账号：`manager` / `123456`。  
项目可归档或永久删除（管理员）；无导出、无 Action 取消。

## 6. 进度与风险

| 概念            | 规则                                              |
| --------------- | ------------------------------------------------- |
| Action 当前进度 | 最新一条日更的 %                                  |
| 当前风险文案    | 最新一条日更的「风险 / 阻塞」                     |
| **开放风险**    | 仅 **进行中** 且最新风险**非空**；草稿 / 完成不计 |
| Action 均进度   | 当前筛选下各 Action 最新进度的算术平均            |
| Task 周进度     | 手填优先；未填 → Action 平均 +「未手填」提示      |
| Task 行负责人   | lead 在前；另有 owner 时「张三 等 N 人」          |

建议：风险解除 → 日更清空风险栏；做完 → 先日更到 100% 再点完成。

## 7. 三个 Tab

页右上角有「使用说明」。本周 / 历史周切换对大屏与工作台共用；**历史最多 10 周、只读**（不可新建 / 日更 / 改状态）。

### 7.1 本周大屏（默认）

面向汇报。

**KPI（精简）：** Task 数 · 有风险 · Action 数 · 均进度（Action 日更算术平均）。

**明细：** 每个 Task 下展示全部非草稿 Action 子行（**含仅 1 条**）；旁注 Task / Action 条数。Task 进度列手填优先。

**明细筛选：**

| Tab                | 含义                                                   |
| ------------------ | ------------------------------------------------------ |
| **需关注**（默认） | 有开放风险，或仍有**进行中** Action（纯草稿不算）      |
| **全部**           | 当前筛选下板内全部 Task                                |
| **已完成**         | **仅 Task.status = 已完成**；Action 全做完不会自动进来 |

排序：有风险优先，再按进度升序。右侧「风险聚焦」列开放风险。支持全屏。

**大屏不展示草稿 Action**；仅草稿的 Task 整行隐藏。本周 0 Action 的空 Task 仍显示（催建）。

### 7.2 工作台

面向执行与维护。

1. 按项目筛选；scope：**我的 Task**（我是 lead）/ **其他** / **全部**  
2. 管理员：新建项目 → 领域 → Task；可对当前筛选项目 **归档**（列表隐藏）或 **永久删除**（含下属数据）  
3. lead：新建本周 Action，或 **复制上周**（单条 / 一键全部）→ 发布  
4. Task 抽屉：填本周 Task 进度；可复制上周  
5. Action 抽屉：改状态、日更、更正；可看**延续历史**（跨周链路）  
6. 管理员可改「周结束」，界面显示推导的周报发送时刻  

历史周隐藏新建入口。空 Task（本周 0 Action）标红提醒。

### 7.3 我的 Action

仅：**当前周** + **owner = 当前用户**。日常写日更、点完成优先用此页。

### 7.4 Action 操作顺序

1. **草稿**：核对标题 / 负责人 / 内容 / 环境 → 发布  
2. **进行中**：每日日更；字段错用更正说明  
3. **做完**：日更到 **100%** → 标记完成（未满按钮禁用；完成后不可日更、不可重开）

## 8. 企微推送（简）

| 项       | 说明                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 日报     | 约每天 **20:00**；Action 视角（今日进展 + 开放风险）；无风险也发；**1 条**         |
| 周报     | **周结束 + 15 分钟**；Task 视角（KPI / 手填进度优先 / 风险）；无风险也发；**1 条** |
| 日更锁定 | 当天 **19:50** 后不可再改今日日更                                                  |
| 长度     | 单条 ≤4096 字节；超长确定性缩短后硬截断                                            |
| 触发     | 部署侧计划任务或管理员手动接口；`dry_run` 可预览                                   |

配置与安装步骤见部署文档 / [test_manage.md](./test_manage.md)，此处不展开。

## 9. 一周清单

### 管理员

- [ ] 项目 / 领域 / Task 人员齐套  
- [ ] 企微 webhook 与定时任务正常  
- [ ] 切周后抽查大屏「需关注」与风险侧栏  

### Task lead（切周后）

- [ ] 为本周要点建 Action，或从上周复制  
- [ ] 指定本周负责人（须在 Task 参与者内）  
- [ ] 填测试内容 / 环境并**发布**  
- [ ] 周结束前填 Task 周进度（推荐）  

### Action owner（每天）

- [ ] 「我的 Action」提交日更（**19:50 前**）  
- [ ] 做完 → 日更到 **100%** → 标记完成

## 10. 常见问题

**Q：切周后上周 Action 呢？**  
A：不会自动带过来。用「新建」或「复制上周」。

**Q：发布后负责人选错了？**  
A：不能改派、不能取消。用更正说明记录，并由正确人选另建一条（或由当前 owner 做到完成）。

**Q：lead 能帮成员写日更吗？**  
A：不能（除非自己是该条 owner，或账号是管理员）。可改状态、追加更正。

**Q：进度 80% 为什么不能完成？**  
A：最新日更须 = **100%**。先提交日更。

**Q：能不能取消 Action？**  
A：不能。草稿可不发布；已发布用更正说明或做到完成。

**Q：完成后能改回进行中 / 再日更吗？**  
A：都不能。完成为终态；可用更正说明补文字。

**Q：「需关注」和「全部」为什么一样多？**  
A：多数 Task 仍有进行中 Action 时两者会接近。纯草稿不算需关注。

**Q：Action 都做完了，Task 为何还不在「已完成」？**  
A：「已完成」只看 Task 状态。请 lead / 管理员在 Task 上设为已完成。

**Q：风险第二天没了怎么写？**  
A：日更把风险栏**留空**保存即可。

**Q：切周日该给哪一周写日更？**  
A：切周当天全天仍写**旧汇报周**；新周 Action 的日更从次日起。

**Q：真实姓名在哪改？**  
A：Admin「用户管理」；看板与推送优先展示真实姓名。

### 规则锚点（以本文与代码为准）

1. 默认切周 **周三 17:00**（可配 week_end）；周报 = 结束 +15 分钟  
2. 发布后不可改派；完成终态；**不支持取消**；完成须进度 100%  
3. 日更仅 owner / 管理员；说明非空；进度不倒退；仅当天；**19:50** 锁定  
4. 开放风险仅统计「进行中」  
5. 大屏「已完成」仅 Task 维度；大屏不展示草稿 Action  
6. 企微日报 / 周报无风险也发；单条截断不拆条
